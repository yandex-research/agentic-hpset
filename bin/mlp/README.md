# `bin/mlp` — modular MLP family

A tabular MLP assembled from interchangeable, per-stage module implementations.
Every pipeline stage (preprocessing, embeddings, model, training loop, optimizer,
loss, inference) is a small registry `{index: builder}`; a run is defined by one
`implementation_indices` dict (which module per stage) plus the sampled
hyperparameters.

This family backs two methods in `exp/`:

- **`mlp`** — the non-agentic baseline: every stage pinned to index `0` (the base
  reference implementation).
- **`agentic-mlp`** — the agentic search over the full module space below.

It additionally hosts the ten **agent-ablation packages** `bin/mlp/<agent>-<idx>/`
(`claude-1`, `claude-2`, `claude-5`, `claude-6`, `claude-7`, `codex-0` … `codex-4`),
which back the `mlp-ablation-<agent>-<idx>` methods in `exp/tuned/` — see
[Agent-ablation packages](#agent-ablation-packages) below.

## Files

| File | Role |
|------|------|
| `modules/<stage>/` | candidate implementations + a `*_MAP` registry in each `__init__.py` |
| `hparams.py` | the search space: HP ranges, per-dataset defaults (`get_default_hps`), the registries, the TPE sampler (`make_sampler`), and the trial budget (`n_trials_for`) |
| `pipeline.py` | `run(config, dataset_root=..., device=...)` replays report configs; `train_and_eval` exposes the lower-level API |
| `core.py` | dataset loading + tensor scaffolding (`Dataset`, `load_raw_arrays`, `to_torch`) |
| `_util.py` | vendored GPU OOM-retry helper used by the inference modules |

## Reconstruct a model from a report

Each `exp/tuned/{mlp,agentic-mlp}/<dataset>/report_<budget>.json` records the
chosen `implementation_indices` and `trial_params`. To rebuild that exact model:

```python
import json
from bin.mlp.pipeline import run

report = json.load(open("exp/tuned/agentic-mlp/california/report_200.json"))
cfg = report["experiments"][0]["config"]
result = run(cfg, dataset_root="data/california", device="cpu")
print(result.report["metrics"]["test"])
# result.predictions contains NumPy arrays; result.model is the fitted model.
```

## Index schema (base vs agentic)

The **agentic-mlp** reports carry the full 10-axis index set matching
`hparams.INDEX_KEYS`. The **base `mlp`** reports predate the split-out
`optimizer`/`loss` axes and use an older key `evaluate_idx` (≡ `inference_idx`);
all of their indices are `0`, i.e. the reference implementation of every stage. Both `run` and `train_and_eval` translate `evaluate_idx` to `inference_idx` and supply the missing index-0 optimizer/loss choices.
Index `0` here matches the base method up to minor classification-support
plumbing (the base `model/mlp.py` differs from index-0 by ~7 lines).

## Agent-ablation packages

Each `bin/mlp/<agent>-<idx>/` directory is the outcome of one independent
end-to-end run of the MLP instruction set (`agentic/mlp/`) by one of two coding
agents (`claude`, `codex`): the agent generated its own module library from the
same baseline, so index `0` of every stage is the shared reference implementation
while every other index is unique to that package. Each package is
self-contained:

| File | Role |
|------|------|
| `modules/<stage>/` | that run's candidate implementations, one registry per stage |
| `modules/__init__.py` | aggregates the registries: `STAGE_KEYS`, `IMPLEMENTATION_REGISTRIES`, `applicable_indices(stage, task)`, `resolve(stage, idx, task)` |
| `core.py` | dataset/tensor scaffolding for that package |
| `mlp.py` | the driver: `main(config, exp)` trains + evaluates one config |

The packages predate this family's `*_idx` key suffixes: their registries use
bare stage keys (`"model"`, `"train"`, …) and per-stage
`APPLICABLE`/`applicable_indices` task filters instead of split `_clf`/`_reg`
registries. The shared driver dependency is vendored at `bin/mlp/_lib/`.

Use `variant` to select the package whose indices appear in the report. The
wrapper imports the hyphenated package name for you. Ablation drivers also need
the shared driver dependencies: install `.[realmlp]` to provide them.

```python
import json
from bin.mlp.pipeline import run

report = json.load(open("exp/tuned/mlp-ablation-claude-1/california/report_200.json"))
cfg = report["experiments"][0]["config"]
result = run(cfg, variant="claude-1", dataset_root="data/california", device="cpu")
print(result.report["metrics"]["test"])
```

Every experiment in those reports records this exact dotted path
(`"function": "bin.mlp.<agent>-<idx>.mlp.main"`), so any number in
`exp/tuned/mlp-ablation-*` resolves to the package that produced it. The
comparison tables are generated by `python -m bin.analysis.gen_agent_ablation`
into `artifacts/agent_ablation/`.
